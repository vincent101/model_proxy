# macOS 手动切换与回滚实施规格（务实）

## 背景与边界

基于 [[tools/model_proxy/.claude/worktrees/qw/feat-windows-unified-cli/docs/designs/2026-11-16-model-proxy统一运行目录与外部权限边界修订|已确认的统一运行目录方案]] §7，本记录订正脚本与假数据演练规格，不改原设计记录或业务代码、不操作生产，也不是部署记录。

**本次用户裁决：**验证新版可用前可不使用 `$route`；若需回滚，允许直接覆盖并丢弃切换后 modelproxy 业务配置、route 和统计的变化，只要求恢复切换前旧版本代码及配置。本订正以此取代本记录原先的统计连续性、保留新版 sidecar 状态等相反要求。切换前须安全保存旧代码引用、实际业务配置、旧 route sidecar（包括不存在）及旧账本；回滚以该快照为准，不把新版账本合并或回迁旧账本。新版账本/日志可作为私有证据保留，但不承诺合并。切换后的新业务改动允许丢失；在途请求和未落盘的配置、route、统计不能由磁盘快照恢复或保证完整，用户须先停稳并自行接受该边界。

真正切换及回滚仍由用户在停服窗口手动调用，脚本不启动、停止或发信号给任何服务，不调用模型。授权只覆盖 modelproxy 原有业务配置、sidecar、账本及其新版数据，不授权覆盖无关用户文件、客户端登录态、外部 `appkey_file` 凭据或旧/新 Git 之外的未知文件，不得损坏共享 `.git` 或嵌套 worktree。

**只读核实，2026-11-18：**主仓 `tools/model_proxy` 在 `master`、HEAD `75475175dbe4f378c18f7ea73f371a17ad1e476a`；W 为其内部 `.claude/worktrees/qw/feat-windows-unified-cli`，HEAD `4486c49b522293c137181caad229c363cc5e44fe`，是旧 HEAD 的直接后继。W 的 `.git` 文件指向主仓 `.git/worktrees/feat-windows-unified-cli`。主仓 `docs/worktrees.md` 已修改且新旧提交不改此文件；存在一个与新版本 tracked 文件同名但内容不同的未跟踪设计文档，另有其他未跟踪文件。两处 `.runtime` 当前均不存在；旧 `/tmp/model_proxy.lock` 存在。以上均是观察，不是之后运行时的保证；每次都要重新预检。本轮未读取真实业务配置、sidecar、账本、日志内容或调用服务。

## 方案设计

### 1. 固定选择：原位置 Git 版本切换，而非整体目录移动

完整项目交付是**内容和运行语义完整**，不是递归替换物理项目目录。保留主仓根、共享 `.git`、嵌套 W 和原有配置数据；先受控保全唯一已知撞名文档，再在主仓对经过预检的目标提交执行 `git merge --ff-only --no-overwrite-ignore <目标完整OID>`。脚本禁止 `git clean`、`git reset --hard`、递归覆盖、移动/删除项目根、`.git` 或 W，也不执行 `git stash`、提交用户数据、改 remote 或自动拉取。Git 命令禁用仓库 hooks，拒绝不能安全控制的 checkout filter、子模块或稀疏检出等未知情况；退出码与后验均要核实。

目标不是硬编码成当前 `4486c49`：实施后脚本和测试需先在 W 提交，目标 OID 是**包含这些交付物的已提交 W HEAD**，须为 `4486c49` 后代、旧 HEAD 后代。切换时 W HEAD、目标 OID、主仓 `master`/旧 OID、工作树登记及共享 Git 实体都须符合记录；目标必须是实际验收的 OID。部署后 master 前进，W 分支仍可指向同一提交，W 不被删除。回滚只在当前 master 仍为本次目标 OID 时以经过逐路径冲突预检的 `git reset --keep <旧OID>` 恢复版本；禁止碰其他提交、分支或授权范围外的改动。若无法证明 Git 操作不会覆盖授权范围外的文件，包括 ignored 文件，拒绝执行；对已识别且授权的业务配置等状态，仅按 §4–5 的快照恢复规则处置，不能扩大到未知文件或未经授权的代码修改。上述 Git 是拟定实现，须用真实 Git/worktree 假数据验收，不能以设计推算宣称已验证。

### 2. 交付物与调用契约

W 中现有交付物及其目标位置：

```text
W/
├── tools/macos_switch.sh                 # 升级入口
├── tools/macos_rollback.sh               # 回滚及中断恢复入口
├── tools/macos_switch_impl.py            # 两入口共用的本机事务实现
├── tests/test_macos_switch_worktree.py   # 真 Git、临时假数据测试
└── docs/designs/2026-11-18-macos手动切换回滚实施规格.md
```

本记录是设计订正；脚本和测试文件已存在，但须依本次裁决修订并重新验收，不能视为已完成。沿用项目已有 `tools/`、`tests/`、`docs/designs/` 目录；脚本及公共实现以 `macos_switch` 命名，供用户调用/维护，测试供实施和复核者使用。实现时更新项目 README 的产物索引与使用说明；不改原已确认记录。新脚本由 W 入口调用，其工作目标是明确提供的主仓根，不能以脚本所在目录误判目标；只能在 macOS、当前用户、预期项目身份和 Git 身份下执行。真实切换不能调用测试专用根或测试注入；测试只在临时目录的假仓库使用注入。

下例展示现有参数形式，修订实现时应简化交互：优先从可信事务记录复用并验证已知 root、端口和旧/新启动上下文，只要求用户补充无法安全推导的值及停稳声明；可保留显式参数作核对，冲突或无法证明时停止。以下不表示简化接口已经实现：

```bash
# 所有变量由用户按实际填写；TARGET 为通过验收并已提交的 W HEAD。
W='tools/model_proxy/.claude/worktrees/qw/feat-windows-unified-cli'
ROOT='tools/model_proxy'
bash "$W/tools/macos_switch.sh" --root "$ROOT" --target "$TARGET" \
  --port "$OLD_PORT" --old-cwd "$OLD_CWD" --new-cwd "$NEW_CWD" \
  --old-home "$OLD_HOME" --new-home "$NEW_HOME" \
  --manual-stopped --auto-start-disabled

# 从升级输出取事务 ID；新实例先由用户停稳。
bash "$W/tools/macos_rollback.sh" --root "$ROOT" --transaction "$TXN" \
  --port "$NEW_PORT" --old-cwd "$NEW_CWD" --new-cwd "$OLD_CWD" \
  --old-home "$NEW_HOME" --new-home "$OLD_HOME" \
  --manual-stopped --auto-start-disabled

# 异常或中断后：仍须停稳、禁自动入口，使用与回滚相同环境参数：
bash "$W/tools/macos_rollback.sh" --root "$ROOT" --transaction "$TXN" \
  --recover --port "$PORT" --old-cwd "$FROM_CWD" --new-cwd "$TO_CWD" \
  --old-home "$FROM_HOME" --new-home "$TO_HOME" \
  --manual-stopped --auto-start-disabled
```

目标简化后的正常回滚入口为 `bash "$W/tools/macos_rollback.sh" --root "$ROOT" --transaction "$TXN" --manual-stopped --auto-start-disabled`：从事务记录取已验证的端口及上下文，缺失、冲突或需要重新确认的值再要求补充；中断恢复同理加 `--recover`。这是待实现目标，并非当前脚本已支持的命令。

`--manual-stopped`、`--auto-start-disabled` 是用户对停稳和禁用所有自动入口/hook 的声明，**不是**自动检测或安全证明。`--port` 是实际服务监听端口，不得猜默认值；如此前有多个可能实例/端口，所有实例须人工停稳，无法枚举或确认则停止。cwd/HOME 为实际旧启动及计划新启动环境，回滚时顺序反过来；不可用当前终端环境冒充已退出服务的历史环境。切换前检查原配置在两个启动上下文内的 `appkey_file` 展开结果、路径/链接身份是否保持同一预期目标，及配置的原始路径、sidecar 位置是否保持；不读取、复制、输出凭据。回滚验证旧快照和旧启动上下文的引用可安全恢复，不要求新版 B 的配置内容或引用与 A 相同；不得通过 B 的未知引用改写外部对象。无法证明历史上下文、恢复目标或旧引用安全则阻断。不支持用户临时自行变更运行路径、配置路径或自定义外部账本的自动迁移；发现与本规格的角色/路径不一致则报告并停止，避免猜测。

### 3. 停稳门禁和锁

- 升级前用户手动停旧服务并禁自动拉起；回滚/恢复前用户分别手动停新服务、禁其入口。检查相关目标入口进程、指定端口的 TCP 监听、旧 `/tmp/model_proxy.lock` 和主仓 `.runtime/anchor.lock`、`.runtime/model_proxy.lock`；遇到不明进程、陌生监听、权限不足或结果不确定一律阻断，不 kill、不清 PID/锁文件。端口为空不能单独证明服务停稳；扫描不能证明所有外部进程都不存在。
- 按现存对象以 `lstat`/打开后 `fstat` 确认同一普通文件及父目录身份，在同一 fd 上非阻塞 `flock(LOCK_EX)`；成功后保持到全部文件/Git 操作结束，操作中及结束时复核路径仍对应 fd。已有锁不 truncate、不替换、不删除，也不按锁文件 PID 判断是否存活。新版固定 anchor 与配置的运行锁均需覆盖；获取顺序为旧锁 → 新 anchor → 新运行锁，固定顺序失败则释放并退出。不存在的旧锁不能仅凭不存在证明停稳：经可信父目录身份检查后独占创建并持有，锁文件保留；竞争或类型/身份未知则停止。新 `.runtime` 若是已存在未知目录则阻断，不接管或改权限；本事务创建的私有目录及锁可用独占创建，之后不删除锁。实际实现须按产品 macOS 权限/身份要求进行验证，不能仅靠 chmod 或新旧锁文件名。
- 旧代码先初始化/截断日志，再以 `open(lock_path, \"w\")` 获取 flock；因此即使脚本持锁，也**不能阻止误启动旧进程先动日志或截断锁内容**。新版旧版各自锁不同；持两套锁也不消除绕过锁、手工启动或非合作写入的竞争。持续禁自动入口并避免并发手动启动是必要前提；操作期间检测到未经授权的并发对象或状态变化就停，不以新版停稳前正常业务更新为异常。不得宣称零竞态。
- 守护/操作脚本不继承锁 fd 给 Git 子进程；脚本自身负责在子进程等待期间持锁。为避免其他切换脚本并发，另在事务私有目录使用单一固定互斥锁；它不替代产品锁。不能因端口 PID 与文件 PID 相同就向它发信号。

### 4. 冲突预检和数据承接

在任何仓库、账本变动前，以 NUL 安全方式比较旧/目标完整 Git 树及主仓 index、工作树的 tracked/非 tracked/**ignored** 文件；检查目标新增/修改/删除的每个路径及父子路径冲突、文件/目录/软链接类型、macOS 卷上的大小写及 Unicode 别名、硬链接和目标身份。Git `--no-overwrite-ignore` 是补充，不代替本次扫描；未知冲突一律阻断。存在暂存改动、冲突 index、进行中的 merge/rebase、被修改且与版本变更相交的授权外 tracked 文件、无法验证的身份等一律阻断；不在本次变更路径上的 `docs/worktrees.md` 修改和其他未跟踪文件保持原地原样。每一变更操作前重验当前相关身份与摘要以防并发替换；不要求业务对象仍与切换前 inode 或摘要相同。

唯一预授权的撞名例外是主仓未跟踪的 `docs/designs/2026-11-12-model-proxy统一内核与原生Windows-CLI设计.md`：先按独占创建在私有事务目录保全字节、权限和摘要并验证，再在身份及摘要仍一致时把原文件迁到该事务目录的明确保留位置，释放新版本 tracked 文件所需路径；不得覆盖任何已有备份。它不是删除或丢弃：报告事务 ID、保留位置，回滚在新 tracked 文件已移除且原路径空闲时将原文件按摘要恢复到原路径。若源文件、目标路径或其父目录的身份不符、同名文件不是普通文件、备份或恢复目的已存在，则阻断；不自动处置其他同类冲突。成功升级后该私有保全件由用户决定何时另存，无自动清理。

切换前在停稳和锁门禁后，识别实际生效的业务配置路径及其引用链，安全备份配置的**原字节、权限/所有权及可用的 ACL/扩展属性、符号链接文本与链接链语义**；按需同时记录存在性、类型、路径和摘要。记录旧 route sidecar 的同等快照；原本不存在也必须明确记录，并验证不存在。旧版本引用为旧完整 OID，并核实对应提交及恢复所需 Git 对象可用；工作树中不属于 Git 版本的配置以独立快照为准。快照私有保存、校验，切换前备份或语义无法可靠保存即停止，不把业务配置/凭据写入 manifest、Git 或日志。升级时配置及 sidecar 沿用原位置，允许新版正常修改；回滚则恢复切换前的字节、权限和链接语义，而非沿用新版内容。`config/runtime_paths.json` 为 tracked 版本配置，升级切到目标提交的六个 `.runtime` 默认值，回滚恢复旧提交六值；若实际文件或环境与本规格不同，停止。

恢复范围按切换前已验证的业务对象及引用目标精确限定，不能因为配置包含 `appkey_file` 就备份或覆盖该外部凭据，也不操作客户端登录态。对链接须先确认路径、链接链与实际写入目标在授权范围内；目录身份变化、链接指向未知对象、硬链接可能牵连授权外文件或无法无损恢复权限/链接语义时阻断。不得沿未知新链接写到外部；恢复操作及父目录检查应防链接替换和路径竞争。正常业务侧原子替换产生的 sidecar inode 变化本身不构成异常：只要路径及父目录安全、对象类型与授权范围可确认且可安全恢复，就覆盖新版 sidecar B 恢复 A；旧 sidecar 不存在时，只移除可确认属于该业务 sidecar 的新版对象并恢复“不存在”，遇未知对象则停止。旧 `.model_proxy.log` 原地保留；新日志可私有保全但不要求合并，也不因此清除其他文件。旧 `/tmp` PID、旧锁、控制记录均不作为新实例授权，不复制为新实例记录。

停稳和锁门禁通过后：旧 `.model_proxy_totals.json` 必须存在、身份可确认、JSON 可解析且满足新旧版本实际可消费的账本 schema；以原字节、权限和链接语义复制为私有快照并校验，再复制到**不存在的**主仓 `.runtime/model_proxy_totals.json`，用同目录独占暂存、fsync、无覆盖提交及后验摘要/身份核验。不能以存在但损坏、空内容或缺失为零账本；旧账本原地保留。没有可靠无覆盖原语时失败退出，不能退化为先检查再覆盖。实际校验仅输出通过/失败，不打印配置、账本内容或敏感字段。

`.runtime` 是产品私有状态：若之前已存在，包括已有账本、日志、记录或未知对象，首次切换一律阻断，不能覆盖或自动认领；仅允许本事务按日志证明创建的目录及对象用于重入恢复。文件权限/ACL 不合格则停止，不自动修复既有文件。回滚不以迁走、软删除或清空新 `.runtime` 为必要步骤；保留原地时须防止旧版本误用新版状态，未来再次升级不得直接认领未知状态。所有敏感备份和事务日志放仓库外 `~/Library/Application Support/model-proxy-migration/<随机事务ID>/`，由当前用户创建并验证私有目录 0700、文件 0600、实际对象及直接父目录安全；禁止进入任何 Git 仓库、CI 或输出敏感内容，异常数据长期保留，不自动清除。

### 5. 事务、回滚和恢复

先独占创建事务目录与 manifest，按阶段持久化：旧/目标 OID、根与 W 身份、精确授权路径和链接/存在性记录、允许迁出的冲突文件摘要与权限、配置/sidecar/旧账本快照的摘要和元数据、每步意图及完成状态；不能记录配置/凭据内容。每步先写 intent 并 fsync，再做操作、验证、写 done；manifest 原子更新并同步必要目录。顺序：`PRECHECK → BACKED_UP → CONFLICT_MOVED → LEDGER_INSTALLED → GIT_ADVANCED → VERIFIED`。`VERIFIED` 后仅打印“版本和磁盘交付完成，服务未启动”，绝不声称服务可用。

中断/错误后停止后续步骤，输出事务 ID、已知阶段及备份位置，不启动服务；可安全清理的仅限该事务独占创建且身份仍一致的未提交临时文件。SIGINT/SIGTERM 做同样收尾；SIGKILL/断电不能捕获，由下一次恢复处理。**禁止盲目重新跑升级或自动 `reset --hard`。** 恢复先重新做停稳、锁和身份门禁，读取最后有效 intent/done，以记录的 OID、index、每个受影响路径及备份摘要核对实际状态：尚未发生的步骤跳过；已发生且与记录一致的步骤可按下述方式逆序撤回；介于两者或身份、内容、Git 状态不匹配的项标记 UNKNOWN，保留所有现场和备份并明确列出对象，停止等待人工处理。任何不能确定安全的 Git 半更新不能靠 `reset --keep` 猜测；不得覆盖未知文件。恢复成功后再次核对旧 HEAD/index、业务配置/sidecar/旧账本快照及权限和链接语义、原文件及嵌套 W、共享 Git 状态，再标 `ROLLED_BACK`；失败保留可重试记录。明确报告这是**多文件可恢复事务，不是全局原子切换**。

正常回滚：

1. 用户手动停稳新版并禁自动入口；锁、端口、进程和 Git 门禁通过。读取并核验本事务切换前的旧 OID、配置、sidecar（含不存在）和旧账本快照、摘要及元数据；核对父目录、链接链和授权目标。版本路径上的无关用户文件或未知改动仍须保留，冲突时停止；新版期间已识别的业务配置、sidecar 和账本变化允许被覆盖或丢弃。
2. 按 §1 安全恢复旧 Git 版本与 tracked 配置；将业务配置和旧账本按快照恢复至原位置，并恢复原字节、权限及链接语义。若已授权的 tracked 业务配置因新版修改而使 `reset --keep` 无法通过，须先验证旧快照和目标提交的对应路径，在事务日志中记录并只将该已识别路径安全恢复到目标提交基线，再执行 Git 回退并覆盖为旧快照；禁止借此清理其他 tracked 改动。此顺序及中断重入均须假仓库实测。可用同目录私有暂存、同步和安全替换实现，但先确认被替换目标确属已授权业务对象、没有链接/硬链接外溢，也不能覆盖快照或无关对象；后验核对快照字节、权限及链接语义。旧账本即使在升级后由已识别业务写成 101，也可恢复切换前 100；变化不能自动解释为授权覆盖未知对象。
3. 将 route sidecar 恢复为旧快照 A（含原权限/链接语义），旧时不存在则安全恢复不存在；新版使用中正常原子替换造成 inode 不同不是拒绝条件，未知目标和不安全父目录仍须阻断。新版配置、route 和统计不保证保留；不要求读取、解析、合并或回写新版 103，可选择私有保全新版账本/日志作为证据，但不是成功回滚的必要条件，也不得影响旧快照。
4. 无覆盖恢复先前撞名用户文档；核对旧 HEAD/index、旧配置/sidecar/账本、权限和链接、无关用户数据、共享 Git 与 W，全部通过后标记完成并报告“旧版本和快照已恢复，服务未启动”。用户自行启动旧服务；不因回滚要求把新目录软删除或清空。再次升级对既有 `.runtime` 的安全处理仍需单独验证，不能默认覆盖未知文件。

恢复过程中逐步记录意图及完成状态；重入时先核验快照、授权目标和当前状态，只对已知可安全重放的步骤继续。替换发生但 done 未写时，以意图、目标摘要/元数据和安全路径核验判定是否已完成；无法区分中断产物与未知对象则为 UNKNOWN，保全现场并停止，不假报成功。Git 半更新及撞名文档同样不得猜测或覆盖未知文件。多文件恢复不是全局原子操作。

### 6. 假数据演练与使用

**新版新端口实测**：只在 W 使用独立假配置、假 sidecar、假账本和空闲的 `127.0.0.1` 新端口；假 supply 只能指向本机受控 mock，不能引用示例配置里的真实网络 URL 或用户凭据。先确认 W 的 `.runtime` 不存在或是本次可识别的假测试状态；W 有其他未知状态则退出，不清除。设置 `MODEL_PROXY_CONFIG` 为 W 下独占创建的私有假配置绝对路径，`MODEL_PROXY_PORT` 为新端口，固定 cwd/HOME 为假测试环境；用 W 的 `model_proxy_cli.sh on/status/off` 或等效经验证路径，仅测试人员针对**自己启动且身份已确认的假实例**操作，验证监听、独立锁、假配置和本地 mock 请求、账本写入、停稳，保全/清理仅限可证明本次创建的假对象。旧服务无需在此阶段停掉，不能访问旧服务、旧锁或真实配置。该启动只属于独立测试，不是切换/回滚脚本行为。若现场安全隔离或空闲端口不能证明则不启动并报告，不能通过“换端口”推定隔离。

真实操作次序：完成上述演练及独立复核 → 用户选停服窗口并手动停旧实例、禁入口 → 用户按 §2 调升级脚本 → 检查成功输出和保留位置 → 用户自行按核验过的 cwd/HOME 启动新版 → 用户核查服务、账本起点及 sidecar。需要回滚时，先由用户停稳新版、禁入口，再手动调用回滚脚本，成功后用户自行启动旧版。此前已确认方案的 Mac/原生 Windows 验收及 WMI 问题处理仍是生产部署门禁，假数据演练不能替代。

## 风险与推演

〔代码观察〕旧锁在日志初始化后获取；独立新版 anchor 不保护旧版。反例：仅测新版 anchor 空闲即复制账本，旧版仍可能写入。故须人工停旧并分别核验。

〔假数据推算〕切换前旧账本 `requests=100`，升级后新版从 100 运行到持久化 103，回滚恢复切换前旧账本 **100**，不把 103 合并或回写；若旧账本位置被已识别业务写成 101，同样按授权恢复 100。旧配置/sidecar A 在新版变为 B 后回滚 A（旧 sidecar 不存在则恢复不存在），正常原子替换导致 inode 变化不阻断。新期间统计和改动可丢失，未落盘增量和在途请求不受快照保证；未知文件或不安全链接不能因此覆盖。该例非实测。

〔Git 推算〕旧主仓的撞名未跟踪文档 A、新提交 tracked 文档 B：先安全迁出 A，再快进落 B；回滚移除 B 后无覆盖恢复 A。若快进前另一个进程在该路径新建 C，重新预检应阻断而非覆盖 C；若中断期间不能证明当前是 A 或 B，则 UNKNOWN。`docs/worktrees.md` 既未处于变更集合又有用户改动，切换前后应逐字节不变。事实以假仓库实验为准。

## 验证方式

全部在 macOS 临时根用真实 Git、真实嵌套 `git worktree` 和假数据构造；不读/写主仓真实配置、账本、日志，不调用外网或模型。测试至少覆盖：

1. 构造与现场相同的旧提交、新提交、共享 `.git`、嵌套 W、修改的 tracked 文档、撞名 untracked 文档、独立 ignored 配置/日志/账本和 sidecar。先演练新版 W 假配置新端口/本地 mock，再完整执行升级和回滚；分别比较 HEAD、index、`git worktree list`、W 可访问性、无关用户文档字节、链接、权限及旧快照。证明目标提交带交付脚本，且升级/回滚未发进程信号、未自行启动服务。
2. 占用旧锁、新 anchor、新锁、指定端口及其他权限不可读的情况逐一拒绝；不持锁但已运行的假进程、不同端口和不可证明的启动环境亦拒绝；重复测试旧实例尝试在持锁期间启动前仍可能先触日志的限制，不误称 flock 可阻断其所有副作用。
3. 以旧账本 100 → 新版运行并持久化 103 → 回滚旧账本 100 为明确断言；旧位置由已识别业务变为 101 亦恢复 100，不回写或合并 103。配置/sidecar A → 新版 B → 回滚 A，比较实际字节、权限及链接语义；覆盖授权 tracked 业务配置变更阻碍 `reset --keep` 时的安全准备和中断重入、旧 sidecar 原本不存在而新版创建后回滚为不存在，以及新版正常原子替换 sidecar 后 inode 变化仍能恢复。新版账本缺失或损坏不应单独阻止恢复有效旧快照；不宣称保全未落盘数据。
4. 测试新版期间新增无关文件保留不变，不覆盖配置指向的外部 `appkey_file` 凭据或客户端登录态；分别注入 ignored/untracked 撞名、目录/文件及大小写/Unicode 别名、危险链接和硬链接、授权外已修改目标 tracked、暂存、变化中的 W/HEAD、首次切换已有未知 `.runtime`、无效或缺失旧账本、不同 cwd/HOME 导致假 `appkey_file` 漂移、权限不明、快照损坏及目标替换为未知对象，安全拒绝且不覆盖无关数据。不可用第二用户/特殊文件系统时标未覆盖。
5. 每个 intent/done 边界分别注入异常和强制中断，包含配置、sidecar 或账本替换已发生但 done 未写、Git 快进/回退中断、撞名文档迁出/恢复中断、并发创建或替换目标；重入恢复结果为可验证恢复或 UNKNOWN 并保全现场，不得覆盖未知对象。重复回滚/恢复不得损坏旧快照、无关文件或扩大授权范围；同时检查真实密钥绝不进 Git 或测试日志。
6. 验证升级时旧账本与新版本的格式兼容及旧版本能消费恢复后的旧快照；不要求新版统计连续性或新版 sidecar 与旧版兼容。测试 shell 入口参数、退出码、帮助、简化手工步骤、停服声明缺失均符合契约。
