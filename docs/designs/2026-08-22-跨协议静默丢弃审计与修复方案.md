# 背景与问题

`model_proxy` 的跨协议转换把若干无法识别、无法等价表达或明确失败的输入/事件静默变成“成功但内容缺失”，其中 Responses→Anthropic 工具丢失使 codex multi-agent 不可用，Responses 上游 `response.failed` 被 Anthropic 客户端看到为正常空消息则直接掩盖真实故障；目标是建立“结构类型严格、已知无损转换、已知降级显式、终态失败绝不伪装成功”的统一边界。

## 审计范围与事实边界

- 代码：`/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/translate.py`、`/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/server.py`、`/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/reasoning/`。
- 组合表仅实现五种组合：同协议两种 PASSTHROUGH，以及 anthropic→chat、responses→anthropic、anthropic→responses；chat 客户端到其他协议均 501（`core/server.py:718`、`core/server.py:1054`）。因此“responses/chat 反向”实际只有 chat 上游→Anthropic 客户端，没有 Chat 客户端转换器。
- 本次补做协议证据：用 codex-cli 0.145.0 经本地 echo server 截获请求，确认顶层含 `client_metadata/include/store/prompt_cache_key`，工具含 `function/custom/namespace`；namespace 工具调用的 Responses 输出是 `function_call + namespace`，custom 工具调用输出是 `custom_tool_call + input`。
- 直连 aigc Anthropic 端点（glm-5.3）探测：标准 function、Responses 原始 namespace/custom/web_search 形状、Anthropic `web_search_20250305` 形状均可获 HTTP 200；但“接受请求”不能证明非标准原始形状被模型识别。只有 Anthropic 标准 web_search 形状可作为候选，仍须强制调用并验证返回块后才能定案。
- 已给定的 gpt-5.6-sol/terra Responses 上游缺陷直接采信，不重复复现。

# 方案设计

## 1. 影响分级

- **T0**：失败被转成成功、错误事件被吞、关键工具整体消失、非法工具参数被替换后继续执行。
- **T1**：功能或多轮语义损失，但有日志或不必然触发错误。
- **T2**：可观测性、缓存、元数据、展示信息损失，不改变主功能。
- **兼容忽略**：协议控制事件确无目标语义，且在显式 allowlist 中。

## 3. 根因

1. **转换器把“协议不支持”实现成 `continue/pass/default`**：结构 union（tool/content/item/event）没有穷尽检查，新增类型自然落入静默丢弃。
2. **成功与终态没有独立建模**：三个流 adapter 的 `finalize()`兼任“正常收尾”和“异常 EOF 补齐”，导致没有 terminal 也伪造 completed/message_stop；`response.failed` 分支甚至直接调用正常 `_emit_finish()`（`translate.py:2235-2250`）。
3. **HTTP 200 被误当业务成功**：server 只按 HTTP status 分流；Responses 的 failed/incomplete 属流内/响应体终态，非流转换前没有统一 envelope 校验（`server.py:1716-1719`、`server.py:1875-1908`）。
4. **转换上下文过窄**：当前 ctx 只保存工具名截断，无法表达 namespace/custom 的可逆映射；r2a 请求函数甚至不返回 ctx（`translate.py:1109-1162`）。
5. **测试固化了错误策略**：例如托管工具“跳过后无 tools”（`tests/test_translate.py:982-993`）、异常 EOF“补 completed/message_stop”（`tests/test_translate.py:1473-1483`、`tests/test_translate.py:2012-2023`），因此现有绿测不能证明 fail-fast。

Responses 铏路必须修：上游限制可以通过切供应协议规避，但代理吞掉 `response.failed` 会让任意未来上游故障都失去可诊断性；r2a 丢 namespace/custom 则使同一 codex 客户端在 Responses supply 可用、切 Anthropic supply 后核心 agent 能力无提示消失，破坏 failover 的语义等价前提。

## 4. 目标架构

### 4.1 统一转换契约

在 `/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/translate.py` 引入内部契约（首期可同文件，稳定后再拆模块）：

- `TranslationContext`：保存 source/target、工具定义映射、调用映射、已知降级项。
- `TranslationError`：包含 phase、source_type、path、reason、upstream error code/type/message、client-visible status。
- `LossPolicy`：每个字段/union type 明确为 `convert | passthrough | declared_drop | reject`；禁止裸 `continue/pass`。
- 顶层未知字段默认 `declared_drop + structured warning`，避免 SDK 加字段即全挂；**工具类型、内容块、output item、终态事件等语义 union 默认 reject**。

不推荐“所有未知字段一律报错”：兼容性过脆；也不推荐“统一 warning 后跳过”：关键功能仍会静默失效。推荐按语义层级分治。

### 4.2 工具注册表

新增 `/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/tool_translation.py`，注册每种 source tool type 的：

- request encoder；
- request-history decoder；
- response non-stream decoder；
- response stream event decoder；
- capability predicate；
- 不可逆损失声明。

任何工具只有“请求定义、历史调用/结果、非流响应、流响应”四面均覆盖后才能标记 enabled，避免只把定义送过去、返回时又吞掉。

### 4.3 终态状态机

三个 stream adapter 统一状态：`OPEN → COMPLETED | INCOMPLETE | FAILED`，终态只能写一次。

- 正常 EOF 只有在已观察到协议终态时允许关闭。
- 未观察到终态的 EOF 是 `FAILED(unexpected_eof)`，不得合成成功。
- 上游 error/failed 映射为目标协议错误事件；已开始 SSE 后不改 HTTP 200，但事件必须可见。
- `incomplete:max_output_tokens` 是可表达的非成功终态：Anthropic 映射 `stop_reason=max_tokens`；其他 incomplete reason 映射 error，除非后续逐项定义。

在 `/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/server.py` 只负责编排与序列化，不再自行拼部分错误骨架；错误转换统一调用 translate 层的 terminal mapper。

**核心逻辑**

1. Responses `failed` 提取优先级：`response.error.{message,type,code}` → 顶层 `error` → 截断原事件；输出 Anthropic `event:error`。
2. Responses `incomplete`：`max_output_tokens` 输出 `message_delta(stop_reason=max_tokens)`；其他 reason 输出 `event:error`。已产出的部分内容保留，但不得再追加正常 end_turn。
3. Anthropic `error` 输出单个 `response.failed`，保持 sequence_number 连续；不得再发 `response.completed`。
4. 非流式 HTTP 200 failed：server 返回 502 + 客户端协议合法 error body；上游 `invalid_prompt` 原 code/type/message进入 message，`final_error` 记录。
5. EOF：adapter 暴露 `terminal_seen`；server 在 buffer 耗尽后调用 `finish_eof()`，由状态决定 no-op 或 error，不再无条件正常 finalize。

**风险与回归点**

- 部分网关可能不发 `[DONE]`，但已发业务终态；以业务终态为准，不强制 transport sentinel。
- Chat 以出现非空 finish_reason 作为业务终态；Responses 以 completed/incomplete/failed；Anthropic 以 message_stop/error。
- Anthropic 客户端是否接受“message_start 后直接 error”需本地 Claude SDK/Claude Code 验证；若不接受，应在首个上游业务事件前延迟发送 message_start，而不是回退到伪成功。

**改动文件与位置**

**namespace 语义**

- Anthropic 没有 namespace 调用概念，不能原样等价表达；采用**可逆扁平化**，不是直接删 namespace：每个子 function 注册为独立 Anthropic tool，wire name 使用 `ns_<hash>__<child>`（遵守目标名称上限），ctx 保存 `{wire_name → namespace, child_name, source_type}`。
- 模型返回 Anthropic tool_use 后，Responses 非流回译为 `function_call`，恢复 `name=<child>` 且增加 `namespace=<namespace>`；流式对应 output_item 也恢复 namespace。
- namespace 内子工具重名、与顶层 function 重名均由 wire name 隔离；tool_choice 指定时经同一映射。
- namespace 空、子项非 function、schema 非 object：请求侧 400；不允许“保留剩余几个”。

**custom/apply_patch 语义**

- Anthropic 只能调用 JSON-schema 工具。将 custom tool 包装成普通 Anthropic tool：`input_schema={type:object, properties:{input:{type:string}}, required:[input], additionalProperties:false}`；description 附加“原始自由文本必须完整放入 input”。ctx 标记 source_type=custom。
- 回译时不产 `function_call`，而产 Responses `custom_tool_call`，恢复 `name/call_id/input`；历史 `custom_tool_call`/`custom_tool_call_output`做逆向 envelope 转换。
- grammar 无法由 Anthropic 强制执行；保留在 ctx 仅用于回显与本地可选校验。模型返回非字符串或违反 grammar 时 fail-fast，不伪造成空 patch。

**web_search 语义**

- 不采用普通 function 伪装：codex 期待托管搜索生命周期，伪装后客户端没有执行器。
- 候选映射仅为 Responses `web_search`/`web_search_preview` → Anthropic `web_search_20250305`；必须先完成“强制搜索→上游返回 `server_tool_use/web_search_tool_result`→回译 Responses `web_search_call` 生命周期→codex 展示/消费”的全链实测。
- 在实测完成且 supply 显式声明 `tool_capabilities.web_search=anthropic_20250305` 前，请求出现 web_search 即 400，错误明确“target supply lacks verified web_search bridge”；禁止继续请求但删掉搜索工具。

**风险与回归点**

- namespace 不是协议原生等价，依赖模型遵循扁平工具描述；需用 spawn_agent 强制调用做 E2E。
- custom JSON envelope 改变提示语义；需验证 codex 能消费回译的 `custom_tool_call`，以及下一轮 output replay。
- web_search 网关“200 接受定义”不等于真的执行；未完成强制调用前不得启用。

## 6. 方案比较与推荐

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 原函数内补 if/日志 | 改动最小 | 新类型继续散落；请求/响应四面易漏；违反开闭原则 | 不采用 |
| B. 注册表 + TranslationContext + 终态状态机 | 类型覆盖集中；新增工具只注册一处；失败语义统一；可分期实施 | 首期改动面较大，需调整现有测试契约 | **推荐** |
| C. 引入第三方全协议转换库 | 初始覆盖可能更广 | 黑盒依赖、供应商方言仍需补丁、控制权下降 | 不采用 |

# 风险与权衡

1. **需用户拍板：未知结构默认策略。** 推荐“顶层未知字段 warning/drop；工具/内容块/output item/终态事件 reject”。若要求绝对兼容，可把内容块改为 warning/drop，但会重新引入静默功能损失，不推荐。
2. **需用户拍板：namespace 可逆扁平化是否接受为等价降级。** 推荐接受；这是 Anthropic 无 namespace 原语时唯一能保住 multi-agent 的方案。若不接受，只能对含 namespace 的 r2a 请求 fail-fast。
3. **需用户拍板：custom JSON envelope。** 推荐启用并配 grammar 本地校验；它不是 wire-level 无损，但能保持 codex apply_patch 调用类型与自由文本内容。若要求协议原生等价，只能 fail-fast。
4. **web_search 暂不拍语义结论。** 已确认网关接受标准 Anthropic定义，但未确认真实执行与回译；按验证门禁决定 enable 或 fail-fast，不猜。
5. **HTTP 200 流内失败映射为 502（非流）**会改变现有调用方看到的状态码，但这是纠正“假成功”；流式已发 200 时只能用协议 error 事件。
6. **迁移/落地代价**：推荐终态需要新增工具注册表、上下文对象、三套流状态机统一终态契约，并反转若干现有测试；分期只控制上线顺序，不降低最终架构。P0 可先落在现有文件内，但接口必须按目标契约设计，避免临时 if 成为永久分叉。
