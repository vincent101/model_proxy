# model_proxy Mac 符号链接配置兼容方案（务实方案）

## 现状与问题

- Mac 服务 bootstrap 将相对配置路径与启动 cwd 拼接，刻意不对 `..` 做词法消除；authority 的私有配置检查允许经安全目录的普通 `..`，但拒绝最终链接和父链链接。服务启动也调用该私有检查，故链接配置目前被拒绝，不能因此认定用户接受了兼容收窄。
- POSIX `config_snapshot` 按打开的文件 FD 和路径标记检测可观察替换，但跟随链接，单独使用不能证明完整链接链及其保护。启动有额外的 Mac 私有检查；不能推断现有热重载每次都已完成等价链保护验证。
- authority 对实际进程启动环境中的配置路径与 CLI 路径进行解析后比较；相同最终目标不自动证明各自链接链安全，也不自动证明两个路径各自的 sidecar 位置一致。
- 配置 helper 直接对指定路径做 `os.replace`：若最后一个组件是符号链接，会替换链接本身。旧 helper 也有这一行为，因此“旧版能用链接路径”不等于“旧版会保留最终链接”。当前写预检使用 `abspath`，对 `symlink/..` 可能检查到与真实访问不同的文件；不能以此预检为实际写入目标的充分证据。
- 原设计 §6.1 明确针对 install/hook 等受控目标规定链接和保护处理；本文借其安全原则设计业务配置写入，**不声称该节已自动授权更改业务配置写入语义**。

## 方案选择与授权边界

| 选项 | 读取、启动与热重载 | 配置写入 | 取舍 |
|---|---|---|---|
| **A：完整支持（推荐）** | 对可证明安全的链接链及 `symlink/..` 支持读取、启动、CLI 控制及手动/自动热重载 | 对可证明安全且在授权范围内的实际目标安全替换，保留链接及可验证保护 | 兼容范围最完整，需补齐链解析、写入和隔离回归；无法证明安全的个例仍拒绝 |
| **B：临时仅读不写** | 同 A | 涉及链接的配置编辑暂时拒绝并明确提示 | 缩短首阶段，但缩窄现有写能力；须用户明确批准临时范围、后续恢复条件与部署节奏 |
| **C：继续拒绝链接** | 拒绝链接配置；普通相对路径和可验证的普通 `..` 仍按既定语义 | 不支持链接配置写入 | 持续收窄兼容；仅在用户明确接受后才可作为产品选择 |

A 不承诺接受全部旧配置：断链、循环、无法可靠识别/读取/验证的目录、文件系统或权限、不能安全保留的链接及越出具体授权范围的写目标均应安全失败，并给出不含秘密的原因。拒绝**无法验证的个例**与默认拒绝所有链接是不同取舍。

## 方案设计

### 1. 路径语义与受保护快照

1. 在底层模块新增或抽取仅适用于 **Mac 业务配置**的共享解析/快照能力，供 server 和 CLI authority 使用；不要全局放宽 `secure_files.capture_target()`，不要随之放宽 runtime 文件、固定锁/记录、install 目标或 Windows 策略。server 不应继续扩大对 CLI authority 的反向依赖。
2. 保留原始配置路径拼写及其启动 cwd；相对路径以原 cwd 为基准，逐组件处理链接的相对/绝对目标与其后的 `..`。不先用 `abspath`、`normpath` 或单次 `resolve` 消去 `..`。对尾部分隔符、`.`、根、非目录中间组件、空值和链接数量上限等 OS 语义提供测试；不能正确表达的情况安全失败，不猜路径。
3. 建议使用持有的目录 FD 逐段 `stat(..., follow_symlinks=False)`、`readlink(..., dir_fd=...)` 与 `open(..., O_NOFOLLOW)`，记录每个实际遍历目录及链接的身份、链接文本和保护证据；处理链接相对目标时从链接所在目录继续，绝对目标从根继续。验证 FD 和路径观察的一致性，并在读取前后及安全边界重走、比较链。链接文本变化、组件替换、目录权限变化、循环/断链、无法读取或检查结果不一致即 UNKNOWN/失败。
4. 以最终文件 FD 读取字节，前后 `fstat`，绑定设备号/inode、类型、大小、时间、owner/group/mode、硬链接数与适用 ACL/其他保护证据。目录同样验证现行信任门槛，包括粘滞共享目录下条目归属，不仅判断 mode；文件系统和 ACL 不能证明可靠时失败。读取快照必须不打印配置字节或凭据，FD/异常清理可验证。
5. 保持原始路径供服务使用，不把规范化目标直接替代它：例如最终链接的不同父目录会改变 `config_path.parent / session_overrides.json`。基于实际服务配置路径检查 sidecar、runtime 和固定状态的冲突，不以同一最终配置 inode 推断 sidecar 同一。相对 `appkey_file` 仍按原调用 cwd 语义处理。

### 2. 启动、控制与热重载

- 服务直接入口和 CLI 启动都使用共享私有快照；将其字节及身份与 listen 解析、`ConfigStore` 初始读取和启动 guard 绑定，重复复核，变化即不 READY。bootstrap 的 cwd/参数/环境及进程身份检查不取消。普通相对路径直接启动不因增加链接支持而退化。
- CLI authority 分别对**服务实际启动环境中的配置路径**和 CLI 配置路径获取受保护快照；证明各自链有效且最终配置身份/内容相符，并处理各自路径衍生 sidecar 的差异。不得只比较规范化字符串或只验证 CLI 链。凭据操作及需当前配置的 restart 无法证明一致时不发送凭据、不发送信号；普通 `off` 仍按既有 last-good 恢复边界独立核验进程并决定是否发信号，不能误改成读取当前损坏配置才能停止，具体回归需覆盖恢复语义。
- 保留安装根、记录、PID、进程启动时间、Python image、服务入口、端口/nonce 和固定锚点等既定证据；flock 用于防重复启动，按既定决策不额外要求证明两把 flock 的同一 PID 持有者。连接建立后核验**该 socket**的实际对端并在同一连接发送，不以端口、配置快照或路径作为进程/对端证据替代；不重连、不凭未知证据发 token。token 的快照在发送前应与再次核验的配置证据绑定，发生变化安全失败。
- 配置首次读取、手动 reload 和自动 marker 探测需使用能验证链与目标保护的同一策略；加载字节、标记和证据来自同一受保护快照。未能稳定读取/解析时，本次不切换原内存快照，不推进错误 marker；后续按现有契约可再次探测。链变化即使最终 inode 不变，也不能绕过保护复核；是否触发重新加载应保持可解释且不漏掉有效变更。
- 手动 reload 只有进入已认证 handler 后才适用失败仍尝试清 cooldown；实际加载结果、清理状态和发送后未知依 §3.1 如实报告。自动重载不清 cooldown。对每请求探测增加的链/ACL 检查需隔离测量，不能为了性能跳过必要安全验证；若性能不可接受，应另提方案，不静默降低证据。

### 3. A 的配置安全写入

1. 先确定**本次具体写入授权范围**；用户选择配置路径不等于授权修改任意外部目标。不能以读取时使用 `/` 为解析根，推断 `/` 内所有文件均被授权写入。链接实际目标、父目录与最终对象须明确且在范围内；超出或无法证明时停止，必要时请求用户裁决。
2. 预览/编辑依据稳定快照，保存原始字节、实际目标、完整链和父目录、目标身份/硬链接数及保护证据。若交互有预览确认，备份前及替换前均重新稳定比较；对于既有无需新增交互的命令，也应在编辑前和提交前比较，不得凭旧快照覆盖变化。变更时停止并要求重新读取，不能自动合并或静默重试。
3. 在已验证的实际目标父目录中创建同卷临时文件，以安全权限完整写入并关闭；复制并验证应保留的 owner/group/mode、适用 ACL 和其他必需保护。不能证明保护等价时提交前失败；硬链接数大于一且不能保留既有关系时拒绝，不能改用原地写绕过安全替换。
4. 复核链接链、实际目标、父目录、身份、原字节及保护后，基于持有的实际目标父目录 FD 原子替换**目标目录项而非符号链接**；提交后复核内容、保护及原链接链，区分未替换、已替换待验、成功、已替换但后验失败。后验失败须报告“目标已改变、保护未知”，停止当前操作后续写入，不静默回滚。备份、标记及 reload 只能反映实际已发生的阶段。
5. 修正业务配置写预检和冲突检查对路径的词法归一化；所有编辑入口、marker 和 helper 的实际提交目标应与预检身份一致。路径/ACL/身份不明时不写、不触发 reload。不得擅自扩大此处规则到日志、账本、sidecar 或 Windows。

### 4. 非原子边界与推演

- **〔纯示意：真实 `..`〕** `other/pivot -> config/inner` 时，`other/pivot/../business.json` 实际指向 `config/business.json`，而词法消除会选 `other/business.json`。若后者是诱饵，使用 `normpath` 做预检而用原路径写入就可能检查错目标；逐段跟随链接后再处理 `..` 才能覆盖此情形。
- **〔纯示意：两条路径〕** CLI 的 `alias-A` 和服务环境中的 `alias-B` 同指一个 inode：终点相同并不证明 `alias-B` 的目录/链接可信，亦不证明二者 sidecar 路径相同。需分别验证路径及服务实际 sidecar；不能只对 A 取快照。
- 链和 FD 的前后比对只能发现**可观察**变化；链解析、最终检查、使用之间仍有非原子窗口，可能出现替换、A→B→A 或不可观察的元数据恢复。不得宣称快照具有事务隔离、消除同用户恶意攻击或保证所有外部变化被检测。
- 写入最终比较与 `replace` 之间仍可发生非协作写入，`replace` 不是 compare-and-swap；即使持有目标父目录 FD 也不能据此保证绝不覆盖并发修改。协作锁不能约束不遵守它的第三方；本方案不假设已存在目标级协作锁或跨进程冻结。部署/操作需明确要求暂停非协作编辑，并按原设计报告后验失败的边界；如必须保证更强隔离，须另行设计并获批准。
- 可观察的读保护检查失败只表明该次读取未安全完成，不等同于已清除服务内存中的旧配置；并发 reload、在途请求和发送后断线仍按原契约报告，不能夸大结果。

## 验证规范与部署门禁

所有运行测试在**专用隔离副本**及假 HOME、假配置、假 runtime 六路径、假账本/日志、专用端口进行；运行前确认路径、进程及外连边界。不得读取或复制生产配置、凭据或日志，不碰生产服务；任何生产、真实客户端、真实上游或真实 Windows 操作须另获授权。只生成测试假数据，不在测试日志打印假 token 以外的敏感内容。

1. **路径和保护**：普通绝对/相对路径、普通 `..`；最终链接、目录链接、多级链接、相对/绝对链接目标及 `symlink/..` 诱饵；`.`、尾部分隔符、文件作目录、断链、循环和上限。验证实际命中目标与 OS 语义一致，保护未知/权限不安全时拒绝。
2. **竞态注入**：逐段和边界注入链接/父目录/目标替换、链接文本变化、ACL/owner/mode 变化、读取中替换、相同目标不同链、修改字节及链 A→B→A 的限制。可观察变化必须失败；对不可观察竞态只记录局限，不写成必然发现。
3. **启动及控制**：直接入口和 CLI `on` 的普通相对路径、链接路径、错误路径；服务环境路径与 CLI 路径不同/同目标不同 sidecar；配置漂移、权限失败及 last-good `off` 恢复。复测 PID、启动时间、入口、nonce、固定锚点和同 socket 对端；伪监听、连后进程变化或证据不足时确认零凭据发送、无自动重连。
4. **热重载**：手动/自动重载链及目标更换、读取/解析失败、权限变化、marker 一致性、旧快照保留；手动进入 handler 后失败仍尝试清 cooldown，自动重载不清；验证回调部分失败及发送后未知按 §3.1 报告。
5. **写入（A）**：实际目标权限和链接关系保留、备份匹配快照、目标越界、硬链接拒绝、预检真实目标与 runtime/sidecar 冲突、确认后外部改写、提交前链替换、暂存/关闭/replace/后验失败、已提交状态与 marker/reload 次数；验证最终链接未被替换且不静默回滚。B 则验证所有链接写操作在写前清晰拒绝；C 验证拒绝及提示，均不得宣称完整兼容。
6. **平台与发布**：用受支持的 Python ≥3.10 和目标 macOS 本机隔离验证实际 `dir_fd`、`readlink`、ACL、文件系统及 socket 能力；测量额外的热路径检查成本。现有本机 `python3` 接口探测为 3.9.6，不能当作目标解释器测试或功能通过。Windows 原生链接/ACL/控制与真实环境尚未完成，Mac 通过不等于 Windows 通过。

上线前须有用户对选项及实施方案的明确确认，完成对应隔离验证和独立复核，并满足原设计各平台门禁；真实环境和部署节奏须另行授权。不得由助手自动操作或重启生产服务，不提交、不合并，除非用户另行授权。
