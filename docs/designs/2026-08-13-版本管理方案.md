# model_proxy 版本管理方案

## 背景

model_proxy 当前无显式版本号：
- `history_versions/` 目录存 v1（proxy.py）下线归档（`proxy-v1-archived-20260724.tar.gz` + ARCHIVE_README.txt），是"大版本下线归档"实践，但无版本号字段。
- 外层 vault repo 有 git tag `pre-data-storage-cleanup-20260808`，是 vault 全库 tag，非 model_proxy 专属。
- README.md 有 frontmatter（`created: 2026-07-17`），无 `version` 字段。
- `core/server.py` 里的 `"version": 3` 是 totals 账本 schema 版本，与产品版本无关。
- 无 VERSION 文件、无 CHANGELOG、无 `__version__`。

model_proxy 现已独立为 git repo（远端 `https://github.com/vincent101/model_proxy.git`，master 分支）。需求：当前版本定为 0.9，设计轻量版本管理机制。

## 设计

### 1. 版本号载体：三件套

| 载体 | 内容 | 作用 | 真相源 |
|------|------|------|--------|
| `VERSION` 文件（根目录纯文本） | `0.9` | 脚本/运行时可读，最权威 | **主** |
| git tag | `v0.9` | git 层面快照，可回溯 | 镜像 |
| README frontmatter `version` + 正文标注 | `0.9` | 给人看，Obsidian 与非 Obsidian 双可读 | 镜像 |

**单一真相源 = VERSION 文件**。tag 和 frontmatter 是它的镜像。

**为什么 VERSION 文件是主而非 tag**：运行时要读版本号暴露到 `/status`，读文件比解析 git tag 简单且无 git 依赖；`git describe --tags` 在无 tag commit 上行为复杂，不如直接读文件可靠。tag 是 git 层面快照镜像，运行时不读它。

**一致性维护**：发版时一个动作更新 VERSION 文件 → 同步改 README frontmatter + 正文 → commit → 在该 commit 上打 git tag。三处不一致时以 VERSION 文件为准。

### 2. 版本号规范

**简化两段式 `MAJOR.MINOR`**（如 `0.9`、`0.10`、`1.0`）：
- `MINOR` 递增（0.9 → 0.10 → 0.11）：功能新增、行为改进、配置 schema 兼容扩展。
- `MAJOR` 递增（0.x → 1.0）：破坏性变更——协议重构、配置 schema 不兼容、入口/端口变更。触发 MAJOR 跳变时，若涉及代码库整体重写，可将旧版 tar.gz 归档后再升 MAJOR（归档目录按需创建，不强制）。
- **不设补丁位**（不写 0.9.1）：补丁即 MINOR 递增。
- `V` 前缀：VERSION 文件和 frontmatter 写**纯数字** `0.9`（不带 V，便于脚本解析）；git tag 带 `v` 前缀 `v0.9`（git 惯例）。

**打 tag 时机**：有用户可感知变化（功能新增、行为变更、配置 schema 变化）时升 MINOR + 打 tag；纯内部重构/bug 修复（用户无感知）不升版本不打 tag。0.9 打完后修 bug 不升 0.10，除非 bug 修复改变了用户可感知的行为。

### 3. 历史归档说明

model_proxy 前身是 `proxy.py`（端口 18888，纯 Anthropic appkey 轮转代理，已于 2026-07-24 下线）。v1/v2 是非正式代号（v1 = proxy.py，v2 = model_proxy.py），与本方案的 0.9/1.0 版本号体系无关。0.9 是 model_proxy 的首个正式版本号，不代表"比 v1 低"——v1 是已下线的另一个代码库，不是 model_proxy 的 1.0 版本。

v1 归档（`history_versions/proxy-v1-archived-20260724.tar.gz`）已于 0.9 清理删除，如需恢复参见 git 历史。

### 4. 变更记录：CHANGELOG.md

轻量，根目录 `CHANGELOG.md`。0.9 是**首个版本化点**，之前不追溯（参见 git log）。

```markdown
# Changelog

## 0.9 (2026-08-13)
- 首个正式版本（model_proxy 从 vault 拆出为独立 git repo）
- 新增 cooldown_rules 策略组（按 errorcode 分组冷却 + failover，URLError sentinel）
- 402 额度耗尽进 failover，6h 冷却
- 新增路径常量统一管理（runtime_paths.json + resolve_runtime_paths，Python/Bash 单一真相源）
- /model_proxy/status 新增 unconfigured_codes 暴露未配策略的 code
- /model_proxy/status 新增 version 字段
```

- 只记"用户可感知的变化"（功能、配置、行为），不记纯重构。
- 每次升版本号时追加一条。

### 5. 运行时可见性：暴露到 /model_proxy/status

`/model_proxy/status` 增加 `version` 字段，读 VERSION 文件（启动时读一次缓存）。

**实现**：
- VERSION 路径硬编码 `_PACKAGE_DIR / "VERSION"`（与 `_PACKAGE_DIR` 常量模式一致），**不进 runtime_paths.json**——VERSION 是静态包元数据，非动态运行时文件。
- `_VERSION` 模块级初始化为 `"unknown"`（与 `_runtime_paths` 同模式：模块级默认值，main() 覆盖），测试 import 时不触发文件读取。
- `main()` 启动时读 VERSION 文件覆盖 `_VERSION`（文件不存在则保持 `"unknown"`，不阻断启动）。
- `_handle_status` 的 `_send_json` 参数加 `"version": _VERSION`。

### 6. 现有 tag 处置

`pre-data-storage-cleanup-20260808` 是外层 vault repo 的 tag，记录 vault 全库状态。model_proxy 已独立为内层 repo，此 tag 属于外层，**不迁移**。model_proxy 内层 repo 从 `v0.9` 起建 tag。

### 7. 落地清单与执行顺序

单阶段（model_proxy 已是独立 repo）：

| # | 文件（绝对路径） | 动作 | 内容 |
|---|------|------|------|
| 1 | `tools/model_proxy/VERSION` | 新建 | `0.9` |
| 2 | `tools/model_proxy/CHANGELOG.md` | 新建 | 0.9 条目（见 §4） |
| 3 | `tools/model_proxy/README.md` | 改 frontmatter + 正文 | frontmatter 加 `version: 0.9`；正文标题下加 `**Version: 0.9**`；§8 补充"已独立为 git repo"说明 |
| 4 | `tools/model_proxy/core/server.py` | 改 | L0 加 `_VERSION = "unknown"` + `_VERSION_FILE = _PACKAGE_DIR / "VERSION"`；`main()` 读 VERSION 覆盖 `_VERSION`；`_handle_status` 加 `"version": _VERSION` |

**执行顺序**：1 → 2 → 3 → 4 → 跑测试 → commit（含 VERSION/CHANGELOG/README/server.py）→ 在该 commit 上打 `v0.9` tag → push。

**tag 时序约束**：VERSION/CHANGELOG 先 commit，再在含版本文件的 commit 上打 tag（否则 tag 指向的快照没有 VERSION 文件，语义矛盾）。

## 风险

1. **三处漂移**：VERSION / frontmatter / tag 不一致。缓解：以 VERSION 为准，发版时同步；人肉维护，发版频率低。
2. **CHANGELOG 维护**：可能忘记记。缓解：只在升版本号时记一条。
3. **运行时读 VERSION 失败**：文件被误删。缓解：`_VERSION = "unknown"` 兜底，不阻断服务。
4. **测试断言**：status 响应新增 `version` 字段，测试需更新断言（值可能是 `"unknown"` 或 `"0.9"`，取决于测试环境有无 VERSION 文件）。

## 不在范围

- CI/.github（独立工作项，model_proxy 当前无自动化测试 CI）
- LICENSE（private repo 暂不加，公开时再补）
