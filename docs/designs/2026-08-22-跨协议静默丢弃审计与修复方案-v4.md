# 背景与问题

跨协议终态 P0 已落地；本期解决两项后续问题：以请求发生时的事实展示跨协议链路，避免当前配置改写历史；将 Anthropic `/v1/messages/count_tokens` 从 Messages 主链剥离，防止误判、命令副作用和错误转换。

## v4 修订记录

本版吸收 v3 独立复核的 3 阻断、2 高、3 中意见：

1. A 的动态真相源改为 ACCESS 新字段 `operation/target_protocol/conversion_kind`，当前配置不得解释历史日志。
2. 旧格式行及 B 修复前误判的 `cc[chat]` 行不进入提醒。
3. B 在 source 后立即识别 operation；nudge、内建命令仅限 messages；count_tokens 在 route/tier 后进入独立分支。
4. operation compatibility 在 attempts/supply 记账前判断；只在同 route 内跳过不兼容 supply。
5. 新建 `core/protocol_hints.py`，消除 core→CLI 反向依赖。
6. 失败摘要定稿为 `全501`、`N空`、`N失败`及组合。
7. 明确 input_tokens 严格类型校验及上游错误 envelope 顺序。
8. 补齐复核要求的 A/B 测试矩阵。

# 方案设计

## 1. P0 已实施归档

commit `4a950a9` 已实现三方向 fail-fast 终态化：failed/incomplete/error/异常 EOF 显式化，未知终止原因默认失败，error 后无成功终态，malformed SSE 失败，合法注释帧忽略，客户端断连不伪造上游失败。715 项测试全绿，三档真实流量通过。

两轮复核结果：

- 方案复核 10 项：终态、stop_reason、handler 测试已纳入 P0；工具注册表、namespace/custom、strict、托管工具 capability、`tool_result.is_error`、中途 system 留在 P1/P2。
- 实施复核 4+1：修复 except 双终态、Chat 坏帧跳过、usage-only message_delta 覆写 stop_reason、BrokenPipe 误判及 SSE 注释帧容忍。

P1 遗留：首帧预读 failover、未知 output item reject、`stop_reason=tool_use` 与有效工具调用一致性、handler 矩阵补强，以及 v2 的双向工具能力治理。

## 2. 公共模块边界

新增 `/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/protocol_hints.py`，只依赖标准库与 `core.reasoning.registry.resolve_protocol`，承载：

- `PROTOCOL_HINT_WINDOW_DAYS = 7`
- `VALID_SOURCES = ("anthropic", "responses", "chat")`
- `protocol_conversion_kind(source, target)`
- `build_protocol_conversion_hints(config)`
- operation 常量与 operation/source/target compatibility 纯判断

依赖方向：

```text
core/protocol_hints.py

```

`_config_ops.py`按需求重导出或直接调用共享纯函数，供 CLI 离线配置操作复用；`core/server.py`不得 import `_config_ops.py`或`_format_ops.py`。

## 3. 需求 A：status 协议转换提醒

### 3.1 数据真相源

动态展示只认请求发生时写入 ACCESS 的事实：

```text
operation=messages target_protocol=anthropic conversion_kind=r2a
```

新增字段语义：

- `operation`：`messages | count_tokens | responses | chat_completions | unknown`。A 仅统计 `messages/responses/chat_completions`，本期展示要求进一步限定 `operation=messages` 的 Anthropic 客户端链路时，其他主协议操作按其真实 kind 同样可纳入；count_tokens 永不纳入。
- `target_protocol`：本次实际选择并发出请求的 supply protocol。
- `conversion_kind`：请求发出时由 source→target 计算，直通为 `passthrough`。

聚合不得用当前 supply 配置反推历史 target protocol；supply 曾由 responses 改 anthropic 时，前后日志各自保持原事实。

旧 ACCESS 行缺任一字段即不进入 A。B 修复前被误判为 chat 的 count_tokens 行自然排除，不按 token/path/date特判。

### 3.2 静态 hints

`build_protocol_conversion_hints(config)`仍生成 `route × tier × supply × source`全量配置预览，字段：

```json
{
  "route": "nation1",
  "tier": "opus",
  "supply": "openai-sol-sankuai-2023",
  "source": "responses",
  "target_protocol": "anthropic",
  "is_conversion": true,
  "kind": "r2a"
}
```

用途仅限：

- `/model_proxy/status`暴露当前配置能力预览。
- formatter 校验日志中的 route/tier/supply 仍存在，避免展示已完全删除的孤儿配置。

不得用 hints补写旧日志缺失字段，也不得覆盖日志中的 target/kind。

kind 固定：`a2r/r2a/a2chat/chat2a/r2chat/chat2r/passthrough`。kind 只表示方向，不代表转换已支持；实际 501 由 ACCESS status 表达。

### 3.3 server 记账时点

扩展 `/Users/vincentwang/Documents/NoteVault/tools/model_proxy/core/server.py:1270-1307`：

- `_acc`初始化三个字段为空。
- source 后立即写 operation。
- 只有实际选择兼容 supply、准备构造上游请求时，写 target_protocol/conversion_kind。
- count_tokens 写 `operation=count_tokens`、`target_protocol=anthropic`、`conversion_kind=passthrough`，但 A loader排除。
- 在“不兼容 supply跳过”阶段不写 supply/target/kind、不增加 attempts。

### 3.4 status JSON与在线边界

`_handle_status()`增加 `protocol_conversion_hints`静态全量。

已核实现状：`model_proxy_cli.sh:164-167`在服务离线时直接退出，不调用 formatter。因此：

- 离线 status 不展示 A，不从本地配置另造第二套动态结果。
- 在线 server JSON 缺 hints（新 CLI 对旧 server）时，A 段静默省略，不报错、不尝试从本地配置替代。

### 3.5 ACCESS loader

在 `_format_ops.py`扩展 `parse_access_line()`读取：token、usage_in/out、operation、target_protocol、conversion_kind。

新增：

```text
load_protocol_conversion_traffic(log_path, hints, now=None,
                                 window_days=PROTOCOL_HINT_WINDOW_DAYS)
```

要求：

- 流式逐行读取文本文件，不 `read()`整文件，不 tail 固定字节。
- 遇到时间戳早于窗口起点可继续扫描，不能假设日志绝对有序；启动截断或少量乱序不影响正确性。
- 聚合键 `(token, source, route, tier, supply, target_protocol, conversion_kind)`；将协议事实纳入键，避免同一 supply 窗口内协议变更被合并。
- 只统计新格式、非 builtin、非 count_tokens、`conversion_kind != passthrough`的行。
- hints缺失时直接返回空；日志组合不在当前 hints时默认不展示，但内部可记 orphan 数用于测试，不用当前 hints改判协议。

互斥状态桶：

- `rejected_501`：status=501。
- `empty`：status=200 且 usage_out=0。
- `success`：status=200 且 usage_out>0。
- `other_failure`：其余 status。

`n`等于四桶和，每行仅进一个桶。

### 3.6 7天日志保留

已核实 `_trim_log()`在启动时执行且只保留最后5000行（`server.py:101-108`，`init_logging()`前段调用），当前无法承诺7天。

改为按时间保留：

- 启动时流式扫描原文件，写临时文件后 `os.replace`，保留最近 `PROTOCOL_HINT_WINDOW_DAYS + 1`天。
- ACCESS、普通日志和 traceback 不拆散：无法解析时间戳的续行归属最近一个带时间戳记录。
- 文件无可解析时间戳或 IO失败时 fail-open保留原文件并 warning，不能误清空。
- 不再设置5000行上限；后续规模问题另做按日轮转。

### 3.7 展示

位置：active sessions 后、cooldown前。仅显示 `n>0`的跨协议聚合，按 n降序；并列按完整键字典序。

定稿格式：

```text
⚠ {token}[{source}] → {route}.{tier} → {supply}[{protocol}] ({kind}) {n}次·{失败摘要}
```

摘要：

- `rejected_501 == n`：`全501`。
- 否则 `failure = rejected_501 + other_failure`。
- empty>0加入`N空`；failure>0加入`N失败`；并存用`·`连接。
- 全成功省略摘要及其前导点。

例：

```text
⚠ cc[responses] → nation1.opus → openai-sol-sankuai-2023[anthropic] (r2a) 12次·2空·3失败
```

段尾：

```text
跨协议链路有语义损失风险，优先用同协议原生接口直连
```

无转换流量时整段不打印；直通永不出现。

## 4. 需求 B：count_tokens

### 4.1 识别与副作用隔离

保留 `detect_source(path, body)`签名。新增独立：

```text
detect_operation(path) -> messages | count_tokens | responses | chat_completions | unknown
```

在 `_forward()`中顺序固定：

1. 解析 body。
2. `source = detect_source(...)`。
3. `operation = detect_operation(path)`，立即写 `_acc.operation`。
4. nudge改写仅 `operation == messages`。
5. `$route`内建命令识别仅 `operation == messages`。
6. 解析 strategy/route/tier。
7. `operation == count_tokens`进入独立 supply选择与转发分支并 return。
8. 只有主生成操作才进入 reasoning decode/remap、预算、translator、SSE逻辑。

精确 path规则：规范化 query、大小写与尾斜杠后，`/v1/messages/count_tokens`→source anthropic + operation count_tokens。其他 messages子路径维持现状，不扩大识别。

这样 count_tokens 即使 body包含 `$route`文本或命中 nudge原文，也无任何配置/sidecar副作用。

### 4.2 独立 supply选择

count_tokens只兼容 protocol=anthropic。兼容判定必须在以下动作之前：

- `self._acc["supply"] = supply_id`
- `attempts += 1`
- reasoning、target model转换、request构造

同 route内规则：

- compatible：选中，才记 supply/attempt=1并发请求。
- incompatible + failover=on：无 cooldown、无 attempt、无 attempt_error，跳过到同 route下一 supply。
- incompatible + failover=off：立即501。
- 同 route候选耗尽：统一501。
- 不跨 route；operation compatibility不是运行故障，不触发既有 route failover。

建议抽出 `select_supply_for_operation()`纯函数，避免在主循环里用特殊 `continue`污染现有状态。

### 4.3 独立 target URL

新增：

```text
build_target_url(supply_url, request_path, operation)
```

count_tokens：

- supply.url规范化尾斜杠后必须以`/v1/messages`结尾。
- 拼接`/count_tokens`，再加净化 query。
- supply.url已含`/count_tokens`视为配置错误，禁止重复追加。
- path大小写只影响识别，不改变配置URL原大小写。
- beta query剔除，其余保持现有重编码语义。

主 messages/responses/chat仍为`supply.url + sanitized_query`，回归结果不变。

### 4.4 请求路径

- body结构原样，若存在model则改为target_model。
- 不调用 nudge、命令、`get_codec()`、reasoning、预算stamp/retry、translator或SSE writer。
- 即使客户端误传`stream=true`，仍按count_tokens非SSE请求处理；建议出站删除`stream`，避免上游方言误解，同时响应始终buffered。
- 鉴权头复用现有appkey替换。

### 4.5 上游响应与错误顺序

处理顺序：

1. `urlopen`抛HTTPError：先读取status/body/Content-Type。
2. 若命中现有cooldown/failover规则，按运行故障处理；但只能对已经实际尝试的Anthropic supply生效。
3. 不触发或耗尽failover后：
   - body是合法Anthropic error envelope `{type:"error", error:{type,message}}`：原样保留status/body/Content-Type。
   - 非法或空body：用`error_body_for_source("anthropic", status, extracted_message)`包装。
4. HTTP 2xx成功：JSON必须满足

```text
isinstance(body, dict)
and type(body.get("input_tokens")) is int
and body["input_tokens"] >= 0
```

`type is int`明确排除bool。校验失败统一返回Anthropic 502 error。

成功时原样透传body与Content-Type；ACCESS usage_in/out保持0，不把估算token记成模型消费。

count_tokens完全不进P0终态机；其非SSE buffered响应与P0不冲突。

# 风险与权衡

1. 旧日志不展示，意味着A上线初期窗口数据不满7天；这是诚实边界，优于用当前配置猜历史。
2. hints用于当前配置校验会隐藏已删除route/supply的历史转换；本期展示定位是“当前仍可操作的链路”。若未来需审计历史，应直接展示日志事实并标`orphan`，另立需求。
3. 日志保留增大磁盘占用；7天是展示承诺所需，下阶段可改按日轮转。
4. count_tokens兼容跳过不计attempt，故ACCESS只记录最终实际请求；若全不兼容，supply为空、status=501，符合“未尝试上游”的事实。
5. `stream=true`被忽略为非SSE属于endpoint语义优先；需测试固定，避免未来误接SSE主链。

# 验证方式

## A测试

1. supply协议在窗口内变更：历史两组仍按各自ACCESS中的target/kind分开显示。
2. 旧格式行、B修复前误判行不进入提醒。
3. 在线JSON缺hints静默省略；离线CLI直接退出，不展示A。
4. 摘要覆盖：N空+N失败并存、部分501、全501、全成功。
5. 超5000行但仍在窗口内全部保留。
6. loader使用流式逐行读取；大文件测试禁止调用无界`read()`。
7. 直通不显示、无转换流量无整段、排序稳定。
8. ACCESS新增字段在成功、501、上游失败路径均符合实际时点。

## B测试

1. count_tokens不触发nudge与`$route`，sidecar/config不变。
2. mock断言不调用reasoning、预算、translator、SSE函数。
3. compatibility：failover on跳过、off立即501、耗尽501；跳过不计attempt、不记supply、不cooldown、不跨route。
4. input_tokens边界：0、正整数通过；负数、浮点、字符串、true、缺字段、非对象均502。
5. 合法Anthropic error原样保留；非法/空错误包装；cooldown/failover先于最终错误写回。
6. 请求含`stream=true`仍返回非SSE buffered JSON。
7. URL覆盖query、尾斜杠、大小写识别、重复追加防护及主三协议回归。
8. CC同款无max_tokens/system body判anthropic/count_tokens并获200。
